# Entwicklung des R-Pakets

R, Python und Julia rufen dieselben Rechenkerne in [`core/`](../core/)
(C-Bibliothek slc und geteilte C++-Kerne) und rechnen bitgleich. Eigener
R-Code sind Eingabeprüfung, Datenaufbereitung, Ablauf, Ergebnisobjekte,
Druck und Grafik. Wer diese Teile ändert, ändert die Python- und die
Julia-Fassung mit (Regeln in [`python/DEVELOPING.md`](../python/DEVELOPING.md)
und [`julia/DEVELOPING.md`](../julia/DEVELOPING.md)) und prüft mit dem
Gleichlauf; die Referenzfälle der Tests erzeugt R
([`tests/README.md`](../tests/README.md)). Die Zuordnung der R-Dateien zu Python und Julia steht in
[`STRUKTUR.md`](../STRUKTUR.md).

## Bauen und prüfen

Aus der Repo-Wurzel, immer mit `LC_ALL=C.UTF-8` (die Referenzen entstanden
unter C.UTF-8):

``` bash
python3 core/sync.py --check                   # Kopien der C-Quellen prüfen (r/src, python/src/core, julia/deps/core)
R CMD INSTALL --preclean -l <Bibliothek> r     # installieren
R CMD build r                                  # Quellarchiv mit Vignette (braucht knitr und rmarkdown)
R CMD check --no-manual SimLev_<Version>.tar.gz
```

Erwartet ist bei `R CMD check` nur die NOTE zur Paketgröße. `.Rbuildignore`
hält Dateien aus dem Archiv heraus, die nur das Repository braucht (u. a.
diese Datei und die Abbildungen der READMEs in `man/figures/`).

## C- und C++-Quellen

Die C-Bibliothek (`slc*.c`, `slc*.h`) und die mit Python und Julia
geteilten C++-Kerne (`simlev_core.h`, `*_core_impl.h`) werden nur in
[`core/`](../core/) geändert (Regeln in [`core/README.md`](../core/README.md));
`src/` enthält Kopien. Nach einer Änderung verteilt
`python3 core/sync.py --write` sie, `--check` vergleicht alle Kopien per
SHA-256. Eigene Dateien des R-Pakets in `src/` sind die `.Call`-Hüllen
(`engine_core.cpp`, `research_core.cpp`, `withdrawal_core.cpp`,
`slc_r*.c`), die Registrierung `init.c` und `simlev_capi.h`. Die
C-Bibliothek wird mit `-std=c99 -ffp-contract=off -fno-fast-math` übersetzt
(`src/Makevars`), wie in Python und Julia.

## Hilfeseiten und Vignette

Die Hilfeseiten in `man/` entstehen größtenteils mit roxygen2 aus den
Kommentaren in `R/` (Kopfzeile „Generated by roxygen2“); einige Seiten,
darunter `simulation.Rd`, `sim_blocks.Rd`, `asset_config.Rd` und
`SimLev-package.Rd`, sind von Hand geschrieben. Das Tutorial ist die
Vignette `vignettes/getting-started.Rmd`; die Python- und Julia-Tutorials
haben dieselben Kapitel. Ihre Beispiele und die der READMEs führt
`tests/werkzeuge/doku/beispiele.sh` aus.

## Tests

Die Tests liegen im Ordner `tests/` des Repositorys, nach Zweck gegliedert,
und gehören nicht zum Paket; `R CMD check` läuft ohne sie. Sie sollen
künftig nur lokal liegen (siehe [`tests/README.md`](../tests/README.md),
Abschnitt „Lokal aufbewahren“).

``` bash
R_LIBS=<Bibliothek mit SimLev> Rscript tests/run.R      # methodik, fehler, ausgabe, schnittstelle (testthat)
tests/run.sh r                                            # dasselbe über den gemeinsamen Einstieg
tests/werkzeuge/gleichlauf/run.sh --quick                 # Gleichlauf: Python und Julia gegen R
tests/schnittstelle/run.sh --check                        # eingefrorene Schnittstelle der drei Sprachen
tests/werkzeuge/doku/beispiele.sh r                       # Beispiele der Doku
```

Neue Referenzfälle erzeugen die Generatoren in `tests/gleichlauf/erzeugen/`
mit dem installierten R-Paket und `jsonlite` (`tests/werkzeuge/erzeugen.sh`).
